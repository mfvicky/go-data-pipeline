# Technical Report — Concurrent Data Processing Pipeline

**Architecture.** An asynchronous Go `net/http` API validates job specifications and stores them through a `JobService` and a GORM-backed PostgreSQL repository. It publishes confirmed, durable job-ID messages to RabbitMQ. Consumers load each persisted specification, execute the pipeline and acknowledge delivery only after the result and final state have been saved. PostgreSQL migrations version the schema, including date-keyed report rows.

**Concurrency.** A configurable pool concurrently streams source records from CSV, JSON or HTTP APIs. Typed channels connect validation and transformation worker pools. A single fan-in aggregation goroutine consumes a bounded channel **while upstream workers run** and computes counts, sums, averages, group-by buckets, or an opt-in multi-source Global Daily Report. A dedicated export goroutine writes JSON/CSV artifacts or a PostgreSQL daily-report table. A separate error collector records rejected rows. A synchronized metrics observer tracks throughput, completion, failures and stage latency. Contexts propagate cancellation and deadlines; producers close channels after their workers finish.

**Data and security.** The Global Daily Report uses source-specific field mappings, validation, transformations and static enrichment. COVID cases/deaths are summed by UTC date, CoinGecko prices select the latest observation per asset and date, and Open-Meteo temperatures are averaged. API-key authentication, request-size limits, rate limiting, security headers, local input confinement, IP/redirect checks and optional outbound hostname allowlists are applied. Output files are job-scoped and survive container recreation through a Docker volume; deleting a terminal job removes its files and database rows.

**Observability and tests.** JSON logs carry request/job identifiers. API progress/results/errors and Prometheus `/metrics` expose behavior. Unit and integration tests cover readers, worker concurrency, cancellation, aggregation, source adapters, report joins, REST routing and artifact cleanup. Docker, RabbitMQ and a live PostgreSQL integration test must be verified in the submission environment.

**Trade-offs.** This is deliberately one API replica: it caches repository state and lacks distributed leases, a transactional outbox, tenant authorization and true exactly-once execution. Although ingestion and aggregation process incrementally, the API still retains all processed records for result retrieval, so job memory usage grows with input size. The bundled multi-source report uses synthetic fixtures for deterministic verification.
